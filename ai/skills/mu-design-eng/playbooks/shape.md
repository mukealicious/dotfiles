# Shape an interface

Produce a design brief, not implementation code. Adapted from Impeccable's shaping
workflow, with proportional discovery and explicit scope.

1. **Discover.** Inspect the request, product context, current UI, data ranges,
   tokens, and constraints. Establish audience, primary action, frequency, realistic
   content, required states, accessibility, and supported devices. Ask only about
   consequential gaps the existing evidence cannot answer.
   **Done:** confirmed facts, assumptions, and unresolved decisions are separate.
2. **Choose direction.** Read [visual design](../references/visual-design.md).
   Describe register, hierarchy, composition, type/color roles, and the interaction
   model. Reuse established decisions. If alternatives are necessary, propose the
   [exploration](explore.md) branch; obtain agreement before creating prototypes.
   **Done:** the direction serves the user's task or message and fits the constraints.
3. **Write the brief.** Include purpose, primary action, scope/fidelity, visual
   direction, layout, content ranges, key states, feedback/recovery, responsive
   behavior, relevant reference pointers, success criteria, and open questions.
   Read [content and states](../references/content-and-states.md) when the brief
   includes forms, onboarding, localization, or state-rich UI.
   **Done:** an implementer can identify what to build and what remains undecided.
4. **Hand off.** Present the brief and request decisions only where they remain.
   Mark an unconfirmed direction as proposed. Write a durable file only when the
   request calls for one. **Done:** the status and next permission boundary are clear;
   planning has not silently become implementation.
